# Immutable market-state record decoding

Baseline is merged Origo `6ac86db9fbe11e53e0fa3fb4470fc7fd8f78bb70` (v3.32.1). The query service still reads the current manifest on every pin. This change memoizes only the pure conversion of a complete selected eight-column row into its immutable StateRecord, bounded to 8,192 entries by the standard-library LRU. Generation, revision, build identity, interval, provisional flag and component hashes are all part of the key; changed metadata therefore cannot reuse an older decoded record. SQL, component/coverage evaluation, cleanup fences, requests and schemas are unchanged.

The 2026-10-04 read-only diagnostic used the actual deployed v3.32.1 module, hash `0db5b29259c640decaf463bf4e201c5dc423e9706797598ee3ddae469151cc4f`. It added the same decorator only in its own process, selecting fresh rows each time. Six alternating steady pairs retained identical full rows and Pin values for all 4,038 live partitions. Pin medians were 207.13 ms baseline and 153.05 ms with decoder reuse (26.1% lower); manifest medians were 117.39 / 117.49 ms. `record-decode-profile.py` is the exact probe and `record-decode-profile.jsonl` is its complete output.

The cold sample includes allocation tracing and is not comparable with steady timing. After the cold sample the traced allocation was 14,344,795 bytes, with a peak of 14,422,441 bytes. This includes cache and client allocations; it is an observation at 4,038 entries, not a worst-case byte bound. Capacity is enforced in entries; concurrent misses may duplicate a decode but do not bypass that bound. There is no time-based source-state cache and no skipped manifest read.

The authentic-capture regression checks two fresh manifest reads while reusing unchanged decoding, then upgrades a real day's component metadata and accepts a canonical day over previously cached provisional minutes. It requires fresh generation/component/coverage values with a warm cache. Eighteen existing comparisons retain full-row/pin equality with the source-current view; the frozen SQL/schema suite applies unchanged.

Explorer [PR #64](https://github.com/Vaquum/Market-State-Cube-Explorer/pull/64) remains unreleased. Its final production-backend comparison after #502 is blocking at n8 (71.27–371.15 ms added latency, 99.9%, above a 62.77 ms floor) and inconclusive at n4/n9. This diagnostic does not clear that gate, certify full-request contention, or authorize a release exception. Required CI, reviews and a final deployed-backend comparison remain necessary.
