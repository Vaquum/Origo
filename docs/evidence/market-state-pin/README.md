# Market-state pin optimization

Slice [#501](https://github.com/Vaquum/Origo/issues/501), based on main `51f6be1`. This changes the market-state `pin` selector, preserving the existing current-partitions view's rows and the subsequent component, gap and cleanup checks. It introduces no source-state cache. The final selector uses DISTINCT to retain the view's row multiplicity even when the anchor log repeats an existing anchor; the real-capture regression reproduces the duplication without DISTINCT.

The 2026-10-04 diagnostic SQL probes returned identical full ordered results for all 3,943 live partitions throughout each run. Six alternating pairs reduced the manifest-query median from 184.57 to 110.72 ms (40.0%). A separate 36-read proxy measured medians of 214.58/264.60 ms for current queries alone/concurrently, and 112.70/154.37 ms for the single-pass queries (41.7% lower concurrently). These are small diagnostic samples, not full-request or release acceptance.

`manifest-profile.py` and `manifest-load-profile.py` are the probes as executed, with their JSONL output. They use the deployed container's existing configuration, readonly statements, four threads, a five-second timeout, 512 MiB, no query-result cache, full-row equality and source-state invalidation. Their SQL prototype predates the final DISTINCT equivalence fix; the host results contained one anchor and did not duplicate rows.

Two complete-request comparisons used the unchanged Explorer `navigation.v2.json` realHost configuration: supported levels 2/4/6/8/9, seed 20260930, 10 alternating A/A pairs, five randomized screening pairs, 20 confirmation pairs when signalled, 10,000 bootstrap resamples and 99.9% intervals. A/A floors remained max(2 ms, 5% baseline median, A/A p95 paired difference). Required-read timing stops when that read returns, before waiting for the concurrent candle worker. Endpoint held-answer caches are cleared; every timed read reaches the supported reader. Historical required-read and candle pins are verified throughout sampling.

The baseline Explorer was deployed main `a42face`; the candidate bridge was Candles head `47f674e`, SHA-256 `c85c7b048a0dd9d810c798cdb6409f0adbe7e5c0c2e187e8f910043dd6f5eac7`. The deployed Origo module matched main `51f6be1`, SHA-256 `ef35fe88d1fedc7f324802dadf907df5163f6eddac0e012ca765002ad635509d`. The isolated candidate replaced only its process's `pin` function with the version from initial PR commit `5136c6d`, module SHA-256 `9e3e7755492dd2659860e6c9de568c350cb4e1db1bed366342293834f1d1b36d`. It predates the DISTINCT fix, so these runs are not final-head certification.

`profile_api.py` started that candidate API on a private container address, with the existing query concurrency, result admission, reader and cleanup validation. Its unique result directory lived on the real shared result volume. It ran no source setup, worker tick, heartbeat or Dagit reporting and changed no served code or schema. The diagnostic process was stopped and its owned result directory removed after both comparisons. Its isolated lifecycle SQLite database means publication contention with the production lifecycle database is not certified by these runs.

`real-performance-optimized.jsonl` compares baseline requests against the deployed API with candidate requests against the isolated optimized API. Bar endpoint screening medians improved by 67–121 ms. Required-read n9 confirmation was inconclusive: interval -197.51–88.78 ms against its 16.35 ms floor. Confirmation medians were 375.94 ms baseline and 410.65 ms candidate. Overall `pass: false`.

`real-performance-matched.jsonl` puts both Explorer arms on the same isolated optimized API. Required-read n9 remained blocking: added-latency interval 53.08–283.03 ms above the 27.88 ms floor. Confirmation medians were 281.62 ms alone and 379.74 ms with candle load; paired median addition 119.25 ms. Required-read n2/n8 were inconclusive; the n6 floor was broad (367.67 ms). Other cases detected no regression at their measured resolution. Overall `pass: false`.

Both reports and their exact executable scripts are retained. No budget was relaxed. The optimization reduces manifest cost but does not eliminate the Candles concurrent-read overhead. Explorer's prior failed reports, unresolved performance review, designated-machine browser protocol and production gate remain outstanding under [slice #62](https://github.com/Vaquum/Market-State-Cube-Explorer/issues/62). Origo's own merge requires applicable CI and the mandated reviews; this evidence does not authorize a Candles rollout.
